## 智能体设计

### 提示词工程

提示词需要进行版本管理，确保每次变更都可追踪、可回滚，并能够关联对应的评测结果。

### 上下文工程

上下文工程包括记忆管理和上下文压缩等，相关设计可参考 Claude Code、Hermes agent、pi agent 的源码。

### Harness 工程

#### 评测体系

Harness 评测体系参考以下资料：

- [Demystifying evals for AI agents（Anthropic）](https://www.anthropic.com/engineering/demystifying-evals-for-ai-agents)
- [中文翻译](https://github.com/oneRede/harness-engineering/blob/main/works/anthropic-demystifying-evals-translation.md#1)

评测层级：

- **组件评测**：测试单个组件的能力。
- **模块评测**：测试 Agent 的完整能力。
- **E2E 评测**：按照 Anthropic 的评测体系搭建，验证从任务输入到最终结果的完整链路。

#### 评测对象

一次评测由以下对象组成：

| 对象 | 说明 |
| --- | --- |
| **Task** | 待完成的任务及其验收标准。 |
| **Trial** | 一次具体的任务执行尝试。 |
| **Transcript** | 任务执行过程中的完整交互记录。 |
| **Outcome** | 任务执行的最终结果及相关指标。 |
| **Grader** | 对执行结果进行评分的评测器，分为三类。 |
| **Result** |
| **Metrics** |

#### 执行规范

1. 修改提示词、工作流或系统版本后，必须重新执行回归评测。
2. 持续更新能力评测数据集，并将能力评测结果控制在 40%～60%。
3. A2A 评测可视为集成测试。任一智能体更新版本后，应对与其存在关联的其他智能体重新执行评测。
